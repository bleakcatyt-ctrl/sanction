# Вектор — работа для ИИ-разработчиков

Сайт-агрегатор вакансий для ML / LLM / NLP / CV / MLOps-инженеров.
Он **сам ищет компании**, которым нужны разработчики, платная подписка Pro оплачивается через **RollyPay**, аккаунты живут в БД.

* **Стек:** Node.js ≥ 22.13, **ноль npm-зависимостей** (встроенные `node:sqlite`, `node:crypto`, `fetch`), ванильный JS на фронте.
* **Дизайн:** собственная дизайн-система (бумага + чернила + «киноварь», Unbounded / Onest / JetBrains Mono, шрифты лежат локально).

## Быстрый старт (разработка)

```bash
npm run dev          # http://localhost:3000 — демо-вакансии + фейковый платёжный шлюз
npm test             # 26 автотестов: безопасность, оплата, вебхуки, краулер
```

`npm run dev` включает `VEKTOR_DEMO=1` (вымышленные вакансии, помечены «Демо») и `VEKTOR_DEV_FAKE_PAYMENTS=1`
(локальная заглушка страницы оплаты; вебхук подписывается и обрабатывается тем же кодом, что боевой). **В production оба режима запрещены — сервер не запустится.**

## Запуск в production

```bash
npm run init-secrets            # создаст ~/.config/vektor/vektor.env (права 600) ВНЕ проекта
$EDITOR ~/.config/vektor/vektor.env   # впишите APP_URL и ключи RollyPay
NODE_ENV=production npm start
```

Готовые `deploy/vektor.service` (systemd с изоляцией) и `deploy/Caddyfile` (HTTPS) — в папке `deploy/`.

### Подключение RollyPay

1. Получите кассу в RollyPay: вам выдадут `api_key` и `signing_secret` ([документация](https://docs.rollypay.io)).
2. Впишите их в файл секретов: `VEKTOR_ROLLYPAY_API_KEY`, `VEKTOR_ROLLYPAY_SIGNING_SECRET`.
3. Укажите в настройках кассы **callback_url**: `https://ВАШ-ДОМЕН/api/webhooks/rollypay`.
4. Сначала оставьте `VEKTOR_ROLLYPAY_TEST_MODE=1` (платежи с `"test": true`, без реальных денег), проверьте весь путь, затем уберите.

Как это работает: сервер создаёт платёж (`POST /api/v1/payments`, `X-API-Key` + уникальный `X-Nonce`) → пользователь уходит на `pay_url` →
RollyPay шлёт вебхук `payment.paid` → сервер проверяет подпись **HMAC-SHA256(`timestamp.body`)**, **перепроверяет платёж запросом `GET /payments/{id}`**,
сверяет `payment_id`, сумму, валюту и тестовый флаг с *нашей* записью заказа и только тогда продлевает подписку (идемпотентно).
Возврат/чарджбек (`payment.refunded`, `payment.chargeback`) отзывает купленный срок. Если вебхук задержался, статус забирается при возврате пользователя на сайт.

Тарифы (серверные константы в `server/billing.js`): Pro 1 мес — 990 ₽, 3 мес — 2 490 ₽, 12 мес — 7 990 ₽. Поменять цены — правим там.

## Где что лежит и почему сайт не взломать «через папку»

| Что | Где | Доступно из интернета |
|---|---|---|
| Раздаваемые файлы | `web/` (только HTML/CSS/JS/шрифты) | да |
| Код сервера | `server/` | **нет** (раздаётся только `web/`) |
| Пароли/ключи RollyPay/секрет сессий | `~/.config/vektor/vektor.env` (chmod 600) **вне проекта** | **нет** |
| База данных | `~/.local/share/vektor/vektor.db` **вне проекта** | **нет** |

Защита, реализованная в коде (и покрытая тестами в `test/security.test.js`):

* Сервер **отказывается стартовать**, если файл секретов или БД указаны внутри папки проекта; в production — если права файла секретов шире `600`, нет секрета сессий, нет https или ключей RollyPay.
* Статика: только из `web/`, защита от path traversal (`..`, `%2e%2e`, `%00`, симлинки через `realpath`), скрытые файлы (`.env`, `.git`) → 404.
* Пароли: **scrypt** (N=32768) + индивидуальная соль, сравнение в постоянное время, выравнивание времени ответа для несуществующих email, политика длины ≥ 10.
* Сессии: случайный токен 256 бит в `HttpOnly; SameSite=Lax; Secure` cookie (`__Host-` префикс на https); в БД лежит только HMAC токена. Смена пароля завершает остальные сессии.
* CSRF: проверка `Origin` + обязательный `X-CSRF-Token` для всех изменяющих запросов.
* Rate limit: вход (по IP и по email, блокировка на 15 мин), регистрация, оплата, API в целом, вебхук.
* **CSP без `unsafe-inline`/`unsafe-eval`**, `X-Frame-Options: DENY`, HSTS, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP/CORP.
* XSS: вакансии из внешних источников чистятся от HTML на сервере и выводятся на клиенте только через `textContent` (в `web/` запрещён `innerHTML`, это проверяет тест). Ссылки — только `http(s)`.
* SQL: только параметризованные запросы. Размеры тел запросов ограничены, таймауты сервера заданы.
* Платежи: цена только на сервере; `pay_url` проверяется на принадлежность домену RollyPay; ключ шлюза никогда не попадает в браузер; вебхук — подпись + окно по времени + перепроверка по API.

Чего код **не** заменяет: HTTPS на прокси (см. `deploy/Caddyfile`), регулярные бэкапы `vektor.db`, обновления Node.js, firewall.

## Как сайт сам находит компании

`server/crawler/` по расписанию обходит открытые API (интервал у каждого источника свой, с учётом их условий):

| Источник | Интервал | Примечание |
|---|---|---|
| Remotive | 6 ч | их условия: ≤ 4 запросов в сутки, указывать источник со ссылкой |
| Arbeitnow | 3 ч | Европа |
| Jobicy | 3 ч | указывать источник, отклик — на оригинальный URL |
| Remote OK | 3 ч | указывать источник со ссылкой без `nofollow` |
| Himalayas | 3 ч | |
| HeadHunter | 3 ч | включается, если задан `VEKTOR_HH_ACCESS_TOKEN` (без токена `api.hh.ru` отвечает 403) |

Каждая вакансия проходит `classify.js`: ИИ-релевантность (0–100), направление (LLM, MLOps, CV, NLP, Research, Data Science…), уровень и стек.
Вакансии группируются по работодателям — это и есть **Радар компаний**. Отдельные запуски: `npm run crawl`.

> **Важно про монетизацию.** Условия Remotive/Jobicy/Remote OK требуют атрибуции и ссылки на оригинал и запрещают собирать регистрации за доступ к их вакансиям.
> Поэтому лента и кнопки «Откликнуться» бесплатны для всех, а Pro продаёт собственную добавленную стоимость: полный радар компаний, совпадение со стеком, сохранённые поиски.
> Если добавите новые источники — сверьтесь с их условиями.

## Ограничения и следующие шаги

* БД — SQLite (WAL): подходит для одного сервера. Для нескольких инстансов нужен Postgres (слой доступа к БД сосредоточен в `server/db.js` и прямых `prepare`-вызовах).
* Rate-limit хранится в памяти процесса.
* Нет писем (подтверждение email, сброс пароля, дайджест новых вакансий) — нужен SMTP.
* Подписка разовая, без автопродления (в API RollyPay нет рекуррентных списаний).
* Нет размещения вакансий работодателями — логичное следующее платное направление.
* Эндпоинты внешних API проверены по их документации/примерам ответов; из среды разработки доступа в интернет не было, поэтому первый боевой сбор стоит посмотреть в логах (`[crawler] …`).
